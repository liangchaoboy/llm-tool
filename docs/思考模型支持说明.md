# 思考模型支持说明

## 一、功能概述

工具现在支持 DeepSeek 思考模型（`deepseek/deepseek-v3.2-251201`），能够根据测试用例类型自动设置 thinking 参数和消息格式。

## 二、支持的模型

### 2.1 DeepSeek 思考模型

**模型名称**:
- `deepseek/deepseek-v3.2-251201`
- `deepseek-v3.2-251201`
- 任何以 `deepseek/` 或 `deepseek` 开头的模型名称

### 2.2 自动检测

工具会自动检测模型名称，如果是 DeepSeek 思考模型，会：
1. 使用新的消息格式（数组格式）
2. 根据测试用例类型自动添加 `thinking` 参数

## 三、请求格式

### 3.1 思考模式（thinking case）

当测试用例类型为 `"thinking"` 时：

```json
{
    "model": "deepseek/deepseek-v3.2-251201",
    "messages": [
        {
            "content": [
                {
                    "text": "什么是太阳",
                    "type": "text"
                }
            ],
            "role": "user"
        }
    ],
    "thinking": {
        "type": "enabled"
    },
    "max_tokens": 1000,
    "temperature": 0.7
}
```

### 3.2 非思考模式（non-thinking case）

当测试用例类型为 `"non_thinking"` 时：

```json
{
    "model": "deepseek/deepseek-v3.2-251201",
    "messages": [
        {
            "content": [
                {
                    "text": "什么是太阳",
                    "type": "text"
                }
            ],
            "role": "user"
        }
    ],
    "thinking": {
        "type": "disabled"
    },
    "max_tokens": 500,
    "temperature": 0.3
}
```

### 3.3 传统模型（非 DeepSeek）

对于其他模型，使用传统的字符串格式：

```json
{
    "model": "gpt-3.5-turbo",
    "messages": [
        {
            "role": "user",
            "content": "什么是太阳"
        }
    ],
    "max_tokens": 500,
    "temperature": 0.3
}
```

## 四、实现细节

### 4.1 API 结构修改

**文件**: `internal/api/client.go`

```go
// Request API请求结构
type Request struct {
    Model       string    `json:"model"`
    Messages    []Message `json:"messages"`
    Stream      bool      `json:"stream,omitempty"`
    MaxTokens   int       `json:"max_tokens,omitempty"`
    Temperature float64   `json:"temperature,omitempty"`
    TopP        float64   `json:"top_p,omitempty"`
    Thinking    *Thinking `json:"thinking,omitempty"` // 新增
}

// Thinking 思考模式配置
type Thinking struct {
    Type string `json:"type"` // "enabled" 或 "disabled"
}

// Message 消息结构（支持两种格式）
type Message struct {
    Role    string      `json:"role"`
    Content interface{} `json:"content"` // 可以是字符串或ContentArray
}

// ContentItem 内容项
type ContentItem struct {
    Text string `json:"text"`
    Type string `json:"type"` // "text"
}

// ContentArray 内容数组
type ContentArray []ContentItem
```

### 4.3 响应解析

**文件**: `internal/tester/tester.go`, `internal/tester/performance.go`

添加了 `extractContentString` 函数，支持从两种格式的响应中提取文本内容：

## 五、使用方法

### 5.1 配置模型

在命令行或配置文件中指定模型：

```bash
./llm-test-tool-v14 \
  -model "deepseek/deepseek-v3.2-251201" \
  -api-key "your-api-key" \
  -base-url "https://api.qnaigc.com/v1/chat/completions" \
  ...
```

### 5.2 测试用例

测试用例文件中的 `type` 字段决定是否启用思考模式：

```json
{
    "id": "test-001",
    "type": "thinking",  // 会启用 thinking: {"type": "enabled"}
    "prompt": "什么是太阳",
    "max_tokens": 1000,
    "temperature": 0.7
}
```

```json
{
    "id": "test-002",
    "type": "non_thinking",  // 会设置 thinking: {"type": "disabled"}
    "prompt": "什么是太阳",
    "max_tokens": 500,
    "temperature": 0.3
}
```

## 六、兼容性

### 6.1 向后兼容

- ✅ 传统模型（非 DeepSeek）继续使用字符串格式的消息
- ✅ 现有测试用例无需修改
- ✅ 响应解析自动处理两种格式

### 6.2 自动适配

- ✅ 根据模型名称自动选择消息格式
- ✅ 根据测试用例类型自动设置 thinking 参数
- ✅ 无需手动配置

## 七、注意事项

1. **模型名称匹配**: 工具通过模型名称前缀判断是否为 DeepSeek 模型
2. **消息格式**: DeepSeek 模型使用数组格式，其他模型使用字符串格式
3. **响应解析**: 工具会自动处理两种格式的响应
4. **测试用例类型**: `type` 字段必须是 `"thinking"` 或 `"non_thinking"`
